# MVP-363 · Stage A 디자인 명세 / Design Integrity Notes

상태: **PO Design Freeze 대기**. 2026-09-29 PO 추가 피드백과 MVP-378 반영. 현재 디자인 명세는 Desktop·Light 전용이다. 이 문서는 Stage B 구현 지시가 아니라 검토할 디자인 기준이다.

## 1. 경험과 정보 위계

**Signal to Pattern**: 분류를 반복할수록 기록이 선명해지는 경험. 브랜드의 M이나 로고를 다시 그리지 않고, 민트 신호의 반복·정렬을 화면의 시각 언어로 확장한다.

1. **첫 인지** — 하나의 넓은 네이비 장면과 상태에 맞는 큰 문장. 소비를 이해하도록 돕는 제품임을 전달한다.
2. **현재 위치** — 분류 필드, 완료율, 완료/미분류/전체 건수. 모두 같은 데이터 집합을 설명한다. 독립 KPI 카드 3개로 분절하지 않는다.
3. **다음 행동** — 장면 안에 단 하나의 채워진 민트 CTA. 업로드 / 남은 내역 정리 / 소비 패턴 탐색 중 현재 상태에 맞는 행동.
4. **실행** — 바로 아래 `내역 작업실`. 대표 화면에서는 미분류 목록, Ready에서는 분류 구성. 데이터 관리 도구를 감추거나 삭제하지 않는다.
5. **제품 여정** — Desktop 우측의 작은 3단계 안내. 보조 정보이며 desktop 장면의 주 콘텐츠를 보완한다. 목표 설정의 새 CTA나 별도 화면은 추가하지 않는다.

메시지와 수치의 관계가 핵심이다. 큰 광고 배너를 기존 도구 위에 얹는 방식으로 끝내지 않는다. 기존의 이중 테이블을 작업실의 `정리할 내역` / `전체 내역` 보기로 묶어 첫 화면의 경쟁을 줄인다. 제목과 사용자 용어는 ‘세척’보다 ‘분류/정리’를 사용하되 공통 Header의 구조·로고·높이는 그대로 두고 MVP-378에 따라 문구를 `이용내역 / 자동 분류 규칙 / 소비 분석`으로 다듬는다. 청소·세탁 은유 아이콘은 실제 적용 단계에서 중립적인 이용내역 아이콘으로 교체 가능하다.

장면 높이는 콘텐츠에 따라 늘어나며 CTA는 분류 시각화보다 먼저 읽힌다. 세부 태그·편집 폼은 기존 상세 동작으로 제공하고 이용내역 편집 기능을 보존한다.

현행 Shell은 내용보다 큰 고정 Header 공간을 예약한다. 목업에서도 이를 반영했다. 이 공간의 축소는 공통 Layout 변경이므로 본 단계의 제안에 포함하지 않는다. 실제 적용 시 현행 Container 여백을 중복하지 않도록 Stage B에서 확인한다.

## 3. Typography / Color / Light

서체는 **Pretendard**. 한국어 줄바꿈은 의미 단위로 유지하고 고정 `<br>`은 콘텐츠 길이에 맞게 검토한다. 숫자는 tabular-nums. H1 650, 행동 750, 본문 400, 보조 제목 600을 중심으로 굵기를 제한한다.

| 역할 | Light |
| --- | --- |
| 기본 배경 | `#F4F8F8` |
| 작업실 표면 | `#FFFFFF` |
| 본문 | `#0D1730` |
| 보조 본문 | `#586574` |
| 작은 강조 글자 | `#006B56` |
| 구분선 | `#DCE6E5` |
| 장면 배경 / 제목 | `#0D1730` / `#F6FBFA` |
| 장면 강조 / CTA | `#31E6B8`, CTA 글자 `#0D1730` |
| 장면 보조 본문 | `#B5C7CE` |
| 분류 미완료 표시 | `#647889`, ‘미분류’ 텍스트 병기 |

미분류는 실패 상태가 아니다. 빨간 경고 배지를 사용하지 않는다. 오류색은 실제 조회·저장 실패에만 사용한다. 금액 증감·수입/지출 의미색을 브랜드 민트로 덮지 않는다. Light의 작은 민트 글자는 `#006B56`을 사용한다.

## 4. 상태별 콘텐츠

| 상태 | 핵심 문장·설명 | 주 CTA | 시각·작업실 변화 |
| --- | --- | --- | --- |
| Empty: T=0 | **내역을 넘어, 당신만의 소비 패턴으로.** / 카드사에서 내려받은 Excel 이용내역을 직접 가져오세요. 흩어진 기록을 정리하면, 나의 소비를 이해할 수 있어요. | Excel 내역 업로드 | 분류율 없음. 0건과 파일→정돈된 기록의 개념 일러스트. 아래에는 지원 파일 및 미리보기→저장 안내. 빈 표 두 개를 노출하지 않음 |
| In Progress: T>0, U>0 | **조금씩 선명해지는, 나의 소비 패턴.** / 전체 {T}건 중 {C}건을 정리했어요. 남은 {U}건에 카테고리를 더해 보세요. | 남은 {U}건 정리하기 | 실제 비율로 분류 필드 표시. 작업실은 `정리할 내역` 선택. 보조 행동은 **지금 소비 분석 보기**. 미분류가 있어도 `/insights` 진입 가능함을 안내. 전체 내역은 작업실 탭에서 접근 |
| Ready: T>0, U=0 | **내역 정리는 끝났어요. 이제, 패턴을 발견할 차례.** / 등록한 {T}건의 분류를 마쳤어요. 정리된 기록에서 나의 소비 패턴을 살펴보세요. | 소비 패턴 살펴보기 | 민트 필드 완성, 100%, 분류 완료. 작업실은 분류 구성 미리보기와 전체 내역. 작은 안내 ‘분류 완료 기준 · AI 분석 결과는 다음 화면에서 확인’ |
| Initial Loading | 소비 기록을 불러오고 있어요. / 현재 데이터 상태를 확인하고 있어요. | 없음 | 장면과 작업실 공간 유지. 숫자 자리 중립 skeleton. 0건·0%를 표시하지 않음 |
| Initial Error | 소비 기록을 확인할 수 없어요. / 다시 불러오면 이어서 정리할 수 있어요. | 다시 불러오기 | 페이지 내 짧은 오류 안내와 재시도. 실패를 Empty로 처리하지 않음. 확인 불가 상태의 수치·CTA 없음 |

공통 브랜드 문장은 In Progress와 Ready의 Desktop 하단에 작게 유지한다. 영문 보조 문장은 장식적 위계이며 국문 정보보다 크거나 진하게 두지 않는다.

**분석 진입은 분류 완료로 잠그지 않는다.** 현행 `AiInsightsPageContent.requestInsight`는 필터 결과 0건만 막고, 미분류 거래는 안내만 표시한다. In Progress에서 주 CTA는 분류를 권장하되 `지금 소비 분석 보기`를 보조 링크로 제공한다. 우측 3단계는 추천 이용 흐름이며 잠금·해제 단계가 아니다. Empty에서도 기존 공통 메뉴는 유지하며, 실제 분석 가능 여부는 기존 분석 화면이 판단한다.

업로드 지원 범위는 현행 모달 기준 **신한카드·KB국민카드 / .xls·.xlsx / 최대 10MB**. 모든 카드사 지원이나 자동 카드 연동을 암시하지 않는다. 새로운 drag-and-drop 업로더를 페이지에 중복 구현하지 않고 기존 모달로 연결한다.

첫 데이터 응답에서 C=0이면 메시지를 **‘소비 패턴을 발견할 첫 단계.’ / ‘{T}건의 내역을 가져왔어요. 카테고리를 정리해 보세요.’**로 바꿔 ‘이미 정리했다’는 긍정적 뉘앙스를 피한다. 미분류 1건일 때도 완료 선언하지 않는다. ‘마지막 한 걸음’ 등 남은 작업을 과장하지 않는 표현은 가능하다.

## 5. 실제 데이터와 표현의 대응

| 표현 | 실제 근거 | 판정 및 제한 |
| --- | --- | --- |
| 전체 T | `overview.transactions.length` | 조회된 전체 등록 거래. 월·소비·순지출 의미 없음 |
| 미분류 U | `getUnclassifiedTransactions(overview.transactions).length` | `!transaction.isClassified`에 근거 |
| 완료 C | T-U | 동일 overview 스냅샷 사용 |
| 완료율 | T>0일 때 C/T×100 | T=0이면 표시하지 않음. U>0이면 정수 표시를 내림하거나 최대 99로 제한. Ready는 U=0으로만 판정 |
| 분류 필드 | C/T | 16열×8행의 추상적 비율 격자. 숫자·범례가 정확한 값이며 셀=거래 1건이 아님. 반올림된 셀 개수로 완료 상태를 판정하지 않음 |
| 미분류 작업 목록 | `overview.transactions` 중 미분류 | `BulkWashPanel`의 선택·단건/일괄 분류 경로 보존 |
| 전체 내역 | `washingQueries.transactions()` 및 categories | 검색·필터·정렬·페이지·수정·태그·삭제 기능 보존 |
| Ready 카테고리 구성 | 완료 내역의 category를 건수로 집계 | 기존 API로 FE 파생 가능. 별도 분석 API 불필요. 상위 3개+나머지 ‘기타(합계)’ 또는 4개 이하면 전부. 건수 내림차순, 동률 이름순. 합계=T. 카테고리 없음/이름 누락은 ‘이름 미확인’으로 명시 |
| 금액 | 기존 거래의 amount | 개별 이용 금액만 표시. 총액·이번 달 소비·절감액 KPI 없음 |
| 마지막 업로드 시간 | **실제 근거 없음** | `fetchWashingOverview`가 `new Date()`로 채운 `lastImportedAt` 사용 금지 |
| AI 완료·추천·절감 | 본 화면에서 확인 불가 | 표시하지 않음. Ready와 무관 |

분류 필드 셀은 왼쪽부터 열 단위로 채운다. 채운 셀 수는 floor(C/T×128), U>0이면 최대 127. 완료가 1건 이상인데 비율이 작아 0셀로 보일 때는 정확한 건수·비율 텍스트를 우선하고, 임의로 1셀=완료건수로 바꾸지 않는다. 아주 작은 비율은 `<1%`, 99% 초과 미완료는 `99%+` 등 오해 없는 표현 가능. 직접 레이블이 있으므로 hover에 필수 정보 의존 금지.

Ready의 카테고리 막대는 **건수 기준**으로만 제목을 붙인다. 가장 큰 값 대비 공통 스케일을 사용하고 끝에 실제 건수를 표기한다. 금액 점유율이나 지출 우열로 해석하는 카피 금지. 시안의 48/32/24/24는 합계 128의 가상 분포이며 앱에 상수로 옮기지 않는다.

### MVP-378 사용자 언어 반영

- Header: `내역 세척 및 관리 → 이용내역`, `규칙 엔진 빌더 → 자동 분류 규칙`, `AI 소비 인사이트 → 소비 분석`. 레이아웃·메뉴 경로는 유지.
- 목록: `미세척/수동 세척 대기 → 미분류`, `일괄 세척 적용 → 선택한 내역 분류하기`, `원천 데이터 → 이용내역`.
- 업로드: `파싱 결과 → 불러온 내역`, `중복 스킵 → 중복된 내역 제외`.
- 내부 파일명·변수명·라우트 `/washing`·API는 변경하지 않는다. MVP-378은 별도 개발·QA 티켓이 아닌 참고 기준이다. 본 Stage B의 관련 화면 안에서 적용한다.

### 코드에서 발견한 정합성 주의

`fetchWashingOverview`는 서버 `isClassified`를 우선하고, 값이 없으면 categoryId/categoryName으로 보완한다. 반면 `SourceDataManagementPanel`은 categoryId/categoryName만 보고 분류를 판단한다. 같은 거래가 서로 다른 상태로 보일 가능성이 있으므로 Stage B에서 표시 조건을 일관되게 적용해야 한다. 이번 Stage A에서는 수정하지 않았다. 상태 의미 변경이 필요하면 별도 근거와 영향 기록을 남긴다.

API 호출이 실패했을 때 빈 배열을 대입해 Empty를 만들지 않는다. 캐시 재조회 중에는 직전의 검증된 화면을 유지하고 ‘업데이트 중’으로 표시한다. 재조회 실패 시 오래된 데이터임을 안내하고, 방금 저장한 결과가 확인되지 않았는데 ‘모두 분류 완료’로 전환하지 않는다.

| 마지막 미분류 해소 | 완료 레이블과 다음 행동 전환 | 자동 라우트 이동·축하 팝업·confetti 없음. 완료 전에도 분석 링크는 계속 사용 가능. 현재 작업 포커스를 빼앗지 않고 polite 알림 |
| Ready CTA | 기존 `/insights`로 이동 | AI 생성 요청이나 성공을 약속하지 않음. MVP-374 장애와 별개 |
| 내역 재분류/삭제/새 업로드 | 실제 데이터로 Hero 재계산 | Ready→In Progress, 삭제 후 Empty 등 역방향 전환도 지원 |
| 작업실 보기 전환 | 선택된 보기 명확히 표시 | 작업 중 선택/입력 유실 방지. 구현 방식에 따라 유지 또는 변경 전 고지. 폼 제출 로직 보존 |

분류 필드 채움·숫자 변화는 300–450ms 이내, 레이블/CTA 전환은 160–220ms crossfade 정도. 수치가 카운팅되는 동안 허위 중간 거래 건수를 스크린리더에 읽지 않는다. 상태 결과를 한 번 알리고, prefers-reduced-motion에서는 즉시 최종 상태 표시. 최초 진입에서 애니메이션 때문에 CTA를 늦게 보여주지 않는다.

접근성: 표·목록·제목의 의미 구조를 보존하고 아이콘만으로 상태를 전달하지 않는다. 그림의 비율은 텍스트 대체를 제공하고 순수 일러스트는 aria-hidden 처리한다. 모든 조작은 키보드로 가능하며 모달 닫힘 후 트리거로 포커스를 복귀한다. 현재 제품의 Suspense/에러 경계에 맞춰 상태를 표현하되, 첫 경험을 별도 에러 페이지로 다시 만들 필요는 없다.

## 7. Stage B 연결점과 보존할 기능

- `WashingPageContent.tsx`: 현재 BulkWashPanel→SourceDataManagementPanel 순서. 새 상태 장면과 작업실 레이아웃의 조합 지점.
- `BulkWashPanel.tsx`: 미분류 전체 목록, 전체/개별 선택, 카테고리 선택, 일괄 적용, 단건 상세 및 저장. Hero의 주 CTA가 이 작업 영역에 연결되어야 한다.
- `SourceDataManagementPanel.tsx`: Excel 모달 상태를 소유하고 있음. 첫 화면의 업로드 CTA에서도 **동일한 기존 모달·처리 경로**가 열리도록 UI 수준에서 연결. 중복 API 구현 금지.
- 전체 내역의 가맹점 검색, 카테고리 필터, 세척 상태 필터, 필터 초기화, 날짜/금액 정렬, 카테고리·태그 편집, 저장, 삭제 확인, 페이지네이션을 보존한다. 목업의 3행 미리보기나 간략한 컬럼을 실제 기능 삭제로 해석하지 않는다.
- `model/core.ts`: 기존 getWashingMetrics의 classificationRate가 반올림됨. 상태 판정은 별도 정확한 건수로 하고 표시는 오해 없게 파생. API·비즈니스 계약 변경은 전제하지 않는다.
- `app/router.tsx`: `/`→`/washing`, 인증 가드 유지. 기존 `/insights`만 연결.
- `AppHeader` 구조, `BrandLogo`, `Layout`, 전역 Theme는 MVP-362 결과 유지. MVP-378 범위의 Header 노출 문구·아이콘 개선은 허용한다. 이 문서의 Shell 구조 재현은 신규 구현 대상이 아니다.

작업실 탭은 UX 제안이며 기존 내부 컴포넌트 재사용 여부는 Stage B 자율이다. 기능을 합치기 위해 불필요하게 데이터 mutation 책임까지 재구축하지 않는다. 다만 두 큰 테이블을 항상 동시에 노출해 첫 화면 정보 위계를 다시 무너뜨리는 방식은 피한다.

## 8. Design Integrity — Essential

1. **단일 중심 장면:** 네이비 면, 큰 한국어 메시지, 민트 신호, 현재 상태와 CTA의 연결. 세 개의 평범한 독립 통계 카드로 대체하지 않는다.
2. **상태별 실제 경험 변화:** Empty의 가치/업로드, In Progress의 정리, Ready의 패턴 탐색. 문구 한 줄만 바꾸고 모든 상태에서 같은 정보 밀도를 유지하지 않는다.
3. **하나의 주 CTA:** 첫 화면에서 업로드·분류·AI 생성을 동일한 강도로 경쟁시키지 않는다. 작업실의 Excel 추가는 보조 강도.
4. **상태의 진실성:** 등록 거래·분류 비율을 설명. T/C/U의 같은 기준, 0과 미확인 구분, 잔여 미분류가 있을 때 완료 오표시 금지. 예시 수치를 제품에 복사 금지.
5. **데이터에서 실제 행동으로:** 정리 CTA가 실제 목록을 열고, 기존 편집/삭제/업로드/분류 기능을 계속 사용할 수 있어야 한다.
6. **Desktop 정보 순서:** 메시지와 다음 행동이 현재 상태를 설명하는 시각화보다 먼저 읽히고, 아래 작업실로 자연스럽게 이어진다.
7. **형태 대비·타이포·여백:** 브랜드 면과 실용적인 작업 표면의 대비, 제목과 보조 정보의 명확한 스케일 차이, 충분한 안쪽 여백 유지.
8. **Light 접근성:** 라이트 배경의 가독성, 색 외의 라벨, focus, reduced motion. 분류는 금융 성과가 아니며 Ready는 AI 성공이 아님.

## 9. Design Integrity — Enhancement

| 요소 | 유지하면 좋은 이유 | 허용되는 경량화 |
| --- | --- | --- |
| 128개 기울어진 민트 셀 | 흩어진 기록과 브랜드 신호의 연결 | 셀 수·기울기·SVG/CSS 방법 변경 가능. 단, 큰 비율 장면과 정확한 숫자/범례는 유지 |
| 미세한 민트 glow | 기술적인 깊이·첫인상 | 단색 네이비 또는 약한 radial gradient로 대체 |
| Empty의 겹친 파일/패턴 일러스트 | 업로드→정리의 가치를 비언어적으로 전달 | 평면 SVG나 CSS 장면으로 대체. 가짜 차트·금액은 넣지 않음 |
| 300–450ms 분류 정렬 모션 | 변경과 완료를 자연스럽게 인지 | opacity 또는 즉시 교체. 자동 카운팅 불필요 |
| Desktop 우측 여정 | 신규 사용자의 맥락 이해 | 간결한 인라인 안내로 대체 가능 |
| Ready의 카테고리 구성 막대 | 정리를 마친 데이터가 의미를 갖기 시작함 | 정확한 카테고리·건수 텍스트 목록으로 대체 가능. 데이터 이름/분류 불일치 시 숨기고 전체 내역 유지 |
| 영문 eyebrow·보조 슬로건 | 편집적 리듬 | 생략 가능 |

Enhancement 대체 시 Stage B는 변경 이유와 사용자에게 보이는 차이를 짧게 기록한다. Essential을 바꿔야 한다면 PO의 확정 방향과 충돌하는지 먼저 판단하며, 무단 축소하지 않는다.

## 10. 제품상 주의사항 및 인계 경계

- 실제 ‘마지막 업로드 시간’ 없음. 조회 시각을 업로드 시각으로 보이게 만들지 않는다.
- 현재 총액은 월/취소/순지출을 엄밀히 구분한 지표가 아니다. 첫 화면 금액 KPI에서 제외.
- 분류 판정 경로 두 개의 잠재 불일치와 100% 반올림을 Stage B가 확인해야 한다.
- 카테고리 API 실패가 overview 전체 실패로 연결되는 현행 구조임. 성공/실패를 목업처럼 임의의 timeout으로 판정하지 않는다.
- Ready는 분류 완료 상태의 안내일 뿐 AI 생성 준비 완료나 응답 성공 보장이 아니다. 운영 장애 MVP-374는 그대로 별도 추적.
- AI Insights Hero·Goal Hero 설계는 범위 밖. 이번 언어/위계/상태 패턴은 후속 작업의 참고가 될 수 있으나 그대로 복사할 의무는 없다.
- 실제 제품 QA는 수행하지 않았다. 독립 목업 렌더링 성공을 앱 구현·운영 QA 통과로 기록하지 않는다.

## 11. PO 검토 지점

새로운 제품 정책 결정은 필요하지 않다. PO는 ① 네이비 중심 장면과 민트 비율 표현의 첫인상, ② 정리 권장 주 CTA와 분석 보조 링크의 균형, ③ 메시지→행동→상태로 이어지는 Desktop 시각 위계를 검토해 Design Freeze 여부를 판단한다. 카테고리 구성 막대·미세 모션은 Enhancement이므로 별도 기능 승인을 전제하지 않는다.

**Stage Gate:** PO가 디자인을 확정한 뒤에만 동일 스레드의 별도 Stage B 프롬프트로 구현한다. MVP-363은 진행 중 유지한다.
