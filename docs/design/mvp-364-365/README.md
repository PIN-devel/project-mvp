# MOTIFIN · Consumption Intelligence → Meaningful Action

MVP-364와 MVP-365의 **통합 Stage A 디자인**. 2026-09-29 통합 브랜치의 화면, API, 계산 코드를 기준으로 작성했다. 제품 구현, 운영 AI 성공 검증, PO Design Freeze는 포함하지 않는다.

## 먼저 보기

1. [독립 인터랙티브 프로토타입](./prototype.html)을 열고 상단 **화면 / 상태** 선택기로 각 장면을 확인한다. 제품 API를 호출하지 않는다.
2. [공통 디자인 언어와 Design Integrity](./shared-design.md)를 확인한다.
3. [MVP-364 화면·상태 명세](./mvp-364/design-spec.md), [MVP-365 화면·수치 명세](./mvp-365/design-spec.md)를 각각 Stage B의 인계 기준으로 사용한다.
4. PO의 추가 결정에 따른 [`/rules` Supporting Experience 대표 시안](./rules/rules.html)과 [경량 인계 명세](./rules/design-spec.md)를 확인한다. 별도 Hero나 규칙 엔진 기능 확장은 아니다.

프로토타입 상단의 `STAGE A · DESIGN SAMPLE` 표시는 전체 화면에 적용된다. **24건, 요약/카드 문장, 추천 목표, 기준·목표 금액, 저장 결과는 모두 시연용 예시**다. 실제 사용자 데이터, 운영 AI 응답 또는 저장 API 성공을 뜻하지 않는다. 프로토타입에서 분석→결과→목표 선택→저장을 시연할 수 있으며, 상태 선택기로 오류·빈 화면과 기존 목표도 독립적으로 확인할 수 있다.

## 하나의 여정, 다른 두 장면

**MVP-364 / 발견:** 깊은 Navy의 읽기 장면에서 정리한 내역의 범위와 AI의 `summary`를 중심에 둔다. 결과의 카드들은 발견의 근거와 후속 선택의 단서다.

**MVP-365 / 결정:** 밝은 작업 표면에서 카테고리별 계획을 비교하고 하나를 선택한다. Navy는 이미 선택한 방향을 표시하고, 금액 도식은 **기준 금액 → 목표 금액**만 비교한다. 확인되지 않은 절감 실적이나 미래 자산 추이는 만들지 않는다.

MVP-363의 신호·여백·큰 한국어 메시지는 계승한다. 첫 진입 Hero의 구성, 공통 Header, 로고와 전역 테마는 재설계하지 않았다. 현재 제품에서는 두 경험 모두 기존 인증 보호 라우트 **`/insights` 내부**에 있으며 별도 Goal 라우트는 없다. 프로토타입의 두 화면 선택은 디자인 검토를 위한 분리다.

`/rules`는 이용내역 정리를 돕는 세 번째 내비게이션 화면으로, 카테고리 관리·규칙 생성·규칙 목록을 차분한 작업 표면에 정돈한다. 주 여정인 발견→목표 선택의 감정적 장면과 구분되는 Supporting Experience다.

## 리뷰와 Stage Gate

- PO는 ① 발견 장면의 요약 위계, ② 목표 선택과 실제 저장 목표의 차이, ③ 수치 표현의 보수적인 경계를 함께 검토한다. 두 디자인은 독립적으로 수정·확정 가능하다.
- MVP-374 복구 전 실제 AI 성공, 추천→저장 통합 경로는 **BLOCKED / NOT TESTED**다. 디자인 샘플의 성공 화면은 이 상태를 바꾸지 않는다.
- Design Freeze 전에는 제품 구현을 시작하지 않는다. Freeze 후 동일 스레드에서 **MVP-364 Stage B → MVP-365 Stage B** 순서로 개별 구현·검증한다. Jira 이슈 완료 처리는 Stage A에서 하지 않는다.

## 검토 자료의 경계

프로토타입은 브라우저에서 직접 열 수 있는 HTML/CSS/JS 산출물이다. 고충실도 기준은 Desktop / Light이며, 좁은 화면에서는 기본적인 재배치만 제공한다. 목업의 Header는 기존 정보 구조를 알아보기 위한 참조이며 새로운 Header 제안이 아니다. Pretendard와 공식 wordmark는 저장소 에셋을 참조한다.
