# `/rules` · Supporting Experience / 경량 Stage A 인계

[Desktop / Light 대표 시안](./rules.html). 이 화면의 카테고리, 미분류 7건, 미리보기 3건, 저장된 규칙 2개는 모두 **Design Sample**이다. 시안은 기존 제품의 입력·미리보기·저장·삭제 절차를 시각적으로 보여주며 실제 API에 요청하지 않는다.

## 역할과 위계

`/rules`는 MVP-363의 정리 작업을 돕고 MVP-364의 소비 분석으로 갈 준비를 돕는 **Supporting Experience**다. 세 번째 큰 Navy Hero를 만들지 않는다. 페이지 상단은 짧은 제목·두 문장 설명·실제 미분류 건수만 둔다. 아래의 도구 영역은 `01 카테고리 관리 → 02 자동 분류 규칙 만들기 → 03 저장된 규칙` 순서로 읽힌다.

- 왼쪽 카테고리 관리: 이름/색상 입력, 등록된 카테고리, 기본/직접 추가 상태, 삭제 동작.
- 오른쪽 규칙 만들기: 반복되는 내역 찾기, 가맹점에 포함된 말/분류할 카테고리/태그, 적용 전 미리보기, 저장·적용 주 행동.
- 오른쪽 하단 저장된 규칙: 키워드·카테고리·태그·현재 적용 건수·삭제. 목록을 카드 장식보다 읽기 쉽게 정렬한다.
- Mint는 주 행동, 순서 번호, 적용 후 카테고리 신호에 사용한다. 파괴적 삭제는 별도의 빨간 텍스트와 확인 모달로 구분한다. 입력·배지·표면의 경계와 radius는 [공통 토큰](../shared-design.md) 사용.

## 기존 기능과 계약 보존

| 기존 인터페이스 | 시안에서의 위치/표현 | 보존 조건 |
| --- | --- | --- |
| `GET /api/rules/patterns` | “반복되는 내역 찾기” | 실제 `keyword`, `occurrences`, `exampleMerchant`, 추천 카테고리를 제안에 대응. 제안 선택은 입력 채우기와 미리보기로 이어짐 |
| `POST /api/rules/dry-run` | “적용 전 미리보기” | `matchCount`, `newlyClassifiedCount`, `overrideCount`, `hasOverrideRisk`, 거래 목록을 근거로 표시. 시안의 현재 분류→적용 후 비교는 선택한 카테고리와 응답으로 구성 |
| `POST /api/rules` | “규칙 저장하고 적용하기” | 기존 키워드·카테고리·선택 태그 저장과 일치 거래 적용. 성공 응답 후 목록/이용내역 재조회 |
| `DELETE /api/rules/{id}` | 저장된 규칙 “삭제” | 기존 확인 모달과 `restoreTransactions` 선택 유지. 복원 선택 시 영향 건수 안내 |
| 카테고리 생성/삭제 | 왼쪽 도구 카드 | 현재 컬러 선택, 중복 이름 검사, 저장/삭제 확인 및 기존 API 유지 |

미리보기는 정보 확인용이다. **현재 제품에서는 미리보기를 거치지 않아도 저장 가능**하며 시안도 이를 새 의무 단계로 만들지 않는다. 시안에서는 미리보기 결과가 펼쳐진 대표 장면을 보여준다. `기존 분류 변경 1건`은 샘플이며 실서비스는 `overrideCount`로 결정한다. 제안/미리보기/저장 실패는 각각 해당 작업 주변에서 안내하고 입력을 보존한다. 목록과 카테고리 조회 실패를 빈 목록으로 표현하지 않는다.

## Stage B 인계

MVP-364의 규칙 화면 P0 카피 정리와 함께 **경량 UI Polish**로 구현한다. `RuleEngineBuilderPage.tsx`의 `/rules` 경로, 인증 가드, `RuleEngineBuilderPanel.tsx`의 생성·패턴 조회·미리보기·적용·삭제 흐름을 그대로 둔다. 카테고리 선택기의 전체 RGB 조정 기능과 태그 필드도 유지한다. 다른 API, 규칙 엔진, 데이터 구조를 만들지 않는다. 미분류 건수는 현재 거래 배열의 분류 상태를 근거로 표시하고, 시안의 7건을 복사하지 않는다. 브랜드 Header는 건드리지 않는다.

**Essential:** 상단의 역할 설명, 세 작업 영역의 명확한 순서, 미리보기의 신규 분류/기존 분류 변경 구분, 저장/삭제의 실제 결과 피드백, 현재 기능과 데이터 계약 보존, 사용자 친화적 명칭.

**Enhancement:** 섹션 번호, 표면 그림자, 장식적인 Mint 포인트, hover 모션은 경량화 가능하다. 카드 배열은 실제 항목 수와 폭에 맞게 조정해도 된다.
