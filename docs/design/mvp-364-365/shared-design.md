# 공통 Visual Language · Experience Contract

## 1. 방향: From signal to choice

사용자에게 전달할 문장은 **“정리한 내역에서 흐름을 발견하고, 내가 바꿀 한 가지를 고른다”**다. MVP-363의 `Signal to Pattern`이 데이터 준비 상태를 설명했다면, MVP-364는 기록의 의미를 읽고 MVP-365는 그 의미를 행동 기준으로 바꾼다. 세 장면의 시각 문법은 이어지되, 같은 Hero를 반복하지 않는다.

| 장면 | 먼저 보이는 것 | 주요 감정 | 주 행동 |
| --- | --- | --- | --- |
| MVP-363 | 준비된 기록/미분류 상태 | 시작할 수 있음 | 이용내역 정리 또는 소비 분석으로 이동 |
| MVP-364 | 분석 범위 + 핵심 발견 | 내 기록을 이해함 | 내 소비 분석하기 / 결과에서 목표 살펴보기 |
| MVP-365 | 선택한 방향 + 기준/목표 비교 | 내가 고를 수 있음 | 목표 선택 및 저장 |

`/rules`는 MVP-363의 분류를 돕는 Supporting Experience로, 짧은 소개와 질서 있는 작업 카드로 구성한다. 별도 Hero나 네 번째 여정 단계는 추가하지 않는다. [대표 시안과 인계](./rules/design-spec.md)를 참고한다.

## 2. 시각 시스템

| 토큰 | 값 / 사용 |
| --- | --- |
| Primary Mint | `#31E6B8` · 하나의 주 행동, 발견 신호, 목표 막대 |
| Deep Navy | `#0D1730` · 발견의 중심 캔버스, 선택한 목표의 정체성 |
| Light Background | `#F4F8F8` · 페이지 바탕 |
| Small Text Accent | `#006B56` · 작은 강조와 라이트 표면 텍스트 |
| Surface | `#FFFFFF` · 범위, 근거, 제안/진행 정보 |
| Border | `#DCE7E8` · 라이트 표면 구획 |
| Body Ink / Muted | `#172842` / `#60727D` · 본문 위계 |
| Warning / Error | `#FFF4E3`·`#A55C0A` / `#FFF0F1`·`#AF4150` · 문구/아이콘과 함께 사용 |
| Radius | 중심 캔버스 24–26px, 섹션 16–21px, 버튼 9–11px |
| Spacing | 기본 8px 계열, 섹션 간 20–28px, 중심 패널 안쪽 31–47px |

Pretendard를 사용한다. Desktop 제목 34–46px / line-height 약 1.18, 장면 제목 30–43px / 1.24, 섹션 제목 23px, 본문 13–16px / 1.6–1.72, 보조 정보 11–12px. 큰 제목은 한국어의 의미 단위에서 줄바꿈한다. `font-weight` 760–850의 대비로 위계를 만들고, 민트는 큰 본문 전체보다 핵심 어구에 사용한다.

### 화면 구성

- 최대 콘텐츠 폭 1180px. 공통 Header 아래 45px 간격에서 페이지 메시지 시작.
- MVP-364: **Navy 해석 면 + White 분석 근거 면**의 비대칭 1.3:0.7 분할. 성공 때 발견 카드를 아래에 배치한다. 장식 원형 신호는 수치 그래프가 아니다.
- MVP-365: **Navy로 선택의 의미를 보여주는 면 + White 목표 선택 작업 면**의 0.86:1.14 분할. 하단의 두 도식은 기준/목표 및 상태를 설명한다.
- 같은 두 열 틀처럼 보이더라도 MVP-364는 읽기와 근거, MVP-365는 선택과 확인으로 시선 및 행동의 방향이 다르다.

## 3. 연결과 행동

```text
정리한 이용내역
  → [MVP-364] 범위 확인 → 분석 실행 → summary/cards 확인
  → 개선 목표 살펴보기
  → [MVP-365] 카테고리별 계획 비교 → 한 개 선택 → 저장
  → 저장된 목표와 현재 상태 확인
```

현재 실제 라우트는 `/insights` 하나다. 프로토타입의 화면 전환은 같은 페이지의 두 정보 영역을 검토하기 쉽게 표현한 것이다. Stage B에서 별도 라우트를 만들지 않는다. AI 결과의 제목/설명과 거래 기반 카테고리 목표는 **출처가 다르다**. 분석의 `summary/cards`를 목표 API의 추천 결과처럼 연결하지 말고, “발견한 흐름을 계기로 목표를 살펴보기”로 카피를 제한한다.

각 상태의 중심 장면에는 주 행동 하나를 둔다. 보조 동작은 낮은 대비로 둔다. 로딩은 진행 중임을 말하고 결과 수치를 선공개하지 않는다. 저장은 서버 응답 뒤에만 성공으로 전환한다. 오류 시 입력/선택/조건을 보존한다. 스켈레톤·신호 회전은 약하게 사용하고 `prefers-reduced-motion`에서는 멈춘다. 키보드 포커스, 색 외 텍스트 상태, 결과 안내용 `aria-live`를 제공한다.

## 4. 사용자 언어

| 내부/기존 표현 | 제안 |
| --- | --- |
| 세척된 카드 이용 내역 | 정리한 이용내역 |
| 인사이트 생성 | 내 소비 분석하기 |
| 미분류 데이터 잔여 | 분류가 필요한 내역이 있어요 |
| 프롬프트 보기/전송 프롬프트 | 분석에 사용되는 정보 |
| 이번 달 AI 추천 목표 | 이용내역에서 고를 수 있는 목표 |
| 누적 절감액 | 검증된 근거가 없으면 표시하지 않음 |
| 절감·자산 추이 | 기준 금액과 목표 금액 / 목표 진행 상태 |

분석은 발견의 가능성을 말하고 사용자를 평가하지 않는다. “중독”, “낭비”, “충동” 같은 판단 표현은 피한다. 금액에는 **기준**, **목표**, **계획상 차이**, **확인된 실적**처럼 종류를 직접 붙인다.

## 5. Design Integrity · 디자인 확정 후 분류

### Shared

**Essential**

1. B · Signal Mint, Pretendard, Light Only, 공식 브랜드 에셋을 유지한다.
2. 상태가 정보 위계와 주 행동을 실제로 바꾼다. Empty와 Error, Loading을 같은 일반 안내로 합치지 않는다.
3. 실제 API/계산으로 근거가 없는 숫자·AI 결과·실적을 제품 화면에 표시하지 않는다. 디자인 샘플은 계속 명시한다.
4. 기존 인증·내비게이션·`/insights` 경로 및 MVP-363의 완료된 UI를 보존한다.
5. 읽기→목표 선택 사이의 CTA와 문장이 사용자의 맥락을 이어준다.

**Enhancement**

- 부드러운 신호 고리, 카드 hover 상승, 부드러운 색 변화는 단색/즉시 전환으로 경량화할 수 있다.
- 영문 eyebrow와 장식적 상태 마커는 의미 위계가 유지되면 생략할 수 있다.
- 동일한 숫자 비교를 보존하면 기준/목표 막대의 시각 처리 방식은 조정할 수 있다.

MVP별 Essential/Enhancement는 각 명세 하단에 따로 기재한다.
