# 공통 Visual Language · Experience Contract

**2026-09-30 PO 결정 · 최종 Visual / Interaction Language.** 이 문서는 MOTIFIN 전 여정의 공통 시각·인터랙션 규칙을 담당한다. MVP-363·364·365의 화면별 명세와 MVP-375의 브랜드 적용 이력에서 강조색·깊이·모션 규칙이 상충하면 본 문서를 우선한다. 화면별 구성과 데이터 계약은 각 명세를 유지한다. 기존 시안·Prototype은 참고 자료이며 재설계하지 않는다.

공식 브랜드 **B · Signal Mint**, 기존 에셋·토큰·Pretendard 및 Light Only를 유지한다. Dark Hero는 Light 제품 안의 어두운 표면이며 신규 다크모드 지원을 뜻하지 않는다. 이번 변경은 디자인 결정과 문서 정리이며 실제 UI 적용·화면 품질 검증 완료를 뜻하지 않는다.

## 1. 방향: From signal to choice

사용자에게 전달할 문장은 **“정리한 내역에서 흐름을 발견하고, 내가 바꿀 한 가지를 고른다”**다. MVP-363의 `Signal to Pattern`이 데이터 준비 상태를 설명했다면, MVP-364는 기록의 의미를 읽고 MVP-365는 그 의미를 행동 기준으로 바꾼다. 세 장면의 시각 문법은 이어지되, 같은 Hero를 반복하지 않는다.

| 장면 | 먼저 보이는 것 | 주요 감정 | 주 행동 |
| --- | --- | --- | --- |
| MVP-363 | 준비된 기록/미분류 상태 | 시작할 수 있음 | 이용내역 정리 또는 소비 분석으로 이동 |
| MVP-364 | 분석 범위 + 핵심 발견 | 내 기록을 이해함 | 내 소비 분석하기 / 결과에서 목표 살펴보기 |
| MVP-365 | 선택한 방향 + 기준/목표 비교 | 내가 고를 수 있음 | 목표 선택 및 저장 |

`/rules`는 MVP-363의 분류를 돕는 Supporting Experience로, 짧은 소개와 질서 있는 작업 카드로 구성한다. 별도 Hero나 네 번째 여정 단계는 추가하지 않는다. [대표 시안과 인계](./rules/design-spec.md)를 참고한다.

## 2. 시각 시스템

| 토큰 | 값 / 사용 |
| --- | --- |
| 기존 Bright Mint | `#31E6B8` · 데이터·진행·작은 브랜드 신호에 선택적으로 사용. 모든 UI의 Universal Primary Accent가 아님 |
| Deep Navy | `#0D1730` · 발견의 중심 캔버스, 선택한 목표의 정체성 |
| Light Background | `#F4F8F8` · 페이지 바탕 |
| 기존 Deep Teal | `#006B56` · 차분한 Brand 표현과 라이트 표면의 작은 강조 텍스트 참고 |
| Surface | `#FFFFFF` · 범위, 근거, 제안/진행 정보 |
| Border | `#DCE7E8` · 라이트 표면 구획 |
| Body Ink / Muted | `#172842` / `#60727D` · 본문 위계 |
| Warning / Error | `#FFF4E3`·`#A55C0A` / `#FFF0F1`·`#AF4150` · 문구/아이콘과 함께 사용 |
| Radius | 중심 캔버스 24–26px, 섹션 16–21px, 버튼 9–11px |
| Spacing | 기본 8px 계열, 섹션 간 20–28px, 중심 패널 안쪽 31–47px |

위 값은 기존 자원의 식별·참고값이며 새로운 팔레트나 CTA의 고정 색상 지시가 아니다. 역할과 주변 표면의 관계를 먼저 판단하고 기존 토큰을 재사용한다. 전역 Mint 값을 일괄 교체하지 않는다.

Pretendard를 사용한다. Desktop 제목 34–46px / line-height 약 1.18, 장면 제목 30–43px / 1.24, 섹션 제목 23px, 본문 13–16px / 1.6–1.72, 보조 정보 11–12px. 큰 제목은 한국어의 의미 단위에서 줄바꿈한다. `font-weight` 760–850의 대비로 위계를 만든다. H1은 의미를 설명하고 CTA는 행동을 이끈다. 제목의 민트 어구가 CTA와 경쟁하면 중립색으로 바꾸거나 강조 범위를 줄인다.

### Brand / Action / Signal

| 역할 | 사용 맥락 | 표현과 위계 |
| --- | --- | --- |
| Brand | Navigation, 활성 선택, 링크, 작은 지속적 강조 | 깊고 차분한 표현으로 신뢰감·지적인 느낌·금융 서비스다운 안정감을 유지. Header의 차분한 활성 Indicator는 방향의 단서이며 모든 요소에 같은 색을 복사하는 기준이 아님 |
| Action | 현재 장면의 Primary Journey Action | Dark Hero와 Light Surface에서 가장 명확한 인터랙션 강조. 밝기 하나가 아니라 대비·배치·무게·여백·반응의 조합으로 구별 |
| Signal | 데이터, Progress, 분류 Grid, 작은 상태 표시, 선택 데이터 포인트, 제한적 Highlight, 작은 브랜드 디테일 | 밝은 Mint의 식별력은 유지하되 면적과 반복을 제한. 넓은 Fill은 Line·낮은 채도/투명도·Neutral/Teal 조합으로 줄이고 Action과 경쟁하지 않음 |

CTA·H1·Progress·분류 Grid·Badge·상태·Illustration·Data Visualization을 하나의 장면으로 평가한다. 모두 Mint여도 같은 강도로 표현하지 않는다. 먼저 보조 요소의 면적·채도·반복을 낮추고 주변 여백을 정돈한다. 색 외 레이블·형태·범례는 보존하며 텍스트 대비를 낮추는 방식으로 해결하지 않는다. 오류·경고·키보드 Focus의 필수 식별력은 CTA 위계와 별개로 보장한다.

### Primary CTA

- 주요 사용자 상태마다 원칙적으로 하나의 Primary Journey Action을 둔다. 작업 표의 저장·삭제 등 국소 행동은 작업 맥락 안에서 유지하되 여정 CTA와 같은 강조로 반복하지 않는다.
- 메시지→다음 행동→상태/근거의 순서가 읽히도록 배치한다. 본문·보조 설명·상태 메타정보·차트와 여백으로 분리하고 Secondary는 낮은 무게의 버튼/링크로 구별한다. Primary를 찾기 위해 Hover하거나 스크롤 안내를 해석해야 하는 구조는 피한다.
- 두 표면 모두에서 Fill/텍스트/경계의 대비와 일관된 높이·굵기를 확보한다. 지나치게 밝은 색, 거대한 버튼, 강한 Glow/Shadow, Pulse/Bounce/큰 Scale로 중요도를 대신하지 않는다.
- 아이콘은 방향·행동의 의미를 보조하고 텍스트보다 앞서 보이지 않는다. Primary의 Hover·Pressed 반응은 Secondary보다 분명하되 절제한다.

### Surface / Border / Shadow

구획은 **Spacing → Background → 필요한 Border → 목적 있는 Shadow** 순으로 판단한다. 같은 깊이·기능의 컴포넌트에는 같은 처리를 사용하고, 이미 여백과 표면으로 구분되면 카드와 경계를 추가하지 않는다.

| 영역 | 우선 수단 | 깊이감 기준 |
| --- | --- | --- |
| Hero | Navy 면과 작업 표면의 대비, 안쪽 여백 | 중심 장면임을 면으로 표현. Floating Card나 Glow를 덧붙이지 않음 |
| 데이터 작업 영역 | 조밀한 정렬·Spacing·필요한 행/그룹 Border | 실용적인 밀도와 읽기 순서를 우선. 각 도구를 별도 카드로 쪼개지 않음 |
| 정적 카드·분석 근거/결과 | Background·Border·그룹 간 여백 | 안정적인 평면. Hover 상승이나 클릭을 암시하는 Shadow 없음 |
| 클릭 가능한 카드·목표 선택 | 선택 Background/Border와 명시적 레이블 | 선택 상태를 Hover·Focus와 구별. 실제 클릭 가능한 카드에만 제한적인 Interactive Depth 허용 |
| 상태 안내 | 인접 배치·텍스트·작은 의미색/Border | 진행·성공·실패를 설명. 모두 떠 있는 패널로 만들지 않음 |

Shadow는 전경/배경, 실제 조작 가능성 또는 그룹 관계를 설명할 때만 사용한다. 모든 카드의 Shadow, 강한 Blur, Glow와 Shadow 혼용, 의미 없는 Hover Elevation을 금지한다. 선택만으로 저장 성공을 암시하지 않는다.

### Icon / Spacing / Density

- 기존 아이콘 자원만 사용한다. 같은 역할·크기군은 크기와 Stroke를 맞추고 텍스트 Baseline·광학적 정렬·아이콘과 텍스트 간격을 함께 확인한다. 큰 아이콘·반복 ThemeIcon 등 의미 없는 장식을 줄인다.
- 행동·상태 아이콘은 의미와 접근 가능한 이름을 유지한다. 장식 아이콘은 보조기술에서 제외하고, 상태를 아이콘만으로 전달하지 않는다.
- Whitespace는 위계 도구다. 같은 그룹은 가깝게, 결정과 보조 정보는 더 분리한다. 기존 Spacing 체계를 재사용하며 모든 화면의 여백을 일괄 확대하지 않는다.
- 업로드·분석 실행·목표 선택처럼 결정이 필요한 장면은 넉넉하게, 거래 표·분류 작업은 실용적인 정보 밀도로 유지한다. 넓은 데이터 시각화와 과밀한 Badge가 CTA의 위치를 가리지 않도록 한다.

### 화면 구성

- 최대 콘텐츠 폭 1180px. 공통 Header 아래 45px 간격에서 페이지 메시지 시작.
- MVP-364: **Navy 해석 면 + White 분석 근거 면**의 비대칭 1.3:0.7 분할. 성공 때 발견 카드를 아래에 배치한다. 장식 원형 신호는 수치 그래프가 아니다.
- MVP-365: **Navy로 선택의 의미를 보여주는 면 + White 목표 선택 작업 면**의 0.86:1.14 분할. 하단의 두 도식은 기준/목표 및 상태를 설명한다.
- 같은 두 열 틀처럼 보이더라도 MVP-364는 읽기와 근거, MVP-365는 선택과 확인으로 시선 및 행동의 방향이 다르다.

## 3. 연결과 행동

```text
정리한 이용내역
  → [MVP-364] 범위 확인 → 분석 실행 → summary/cards 확인
  → 개선 목표 살펴보기
  → [MVP-365] 카테고리별 계획 비교 → 한 개 선택 → 저장
  → 저장된 목표와 현재 상태 확인
```

현재 실제 라우트는 `/insights` 하나다. 프로토타입의 화면 전환은 같은 페이지의 두 정보 영역을 검토하기 쉽게 표현한 것이다. Stage B에서 별도 라우트를 만들지 않는다. AI 결과의 제목/설명과 거래 기반 카테고리 목표는 **출처가 다르다**. 분석의 `summary/cards`를 목표 API의 추천 결과처럼 연결하지 말고, “발견한 흐름을 계기로 목표를 살펴보기”로 카피를 제한한다.

### 상태별 Primary Journey Action

별도 Landing Page 없이 `/washing` Empty를 첫 경험으로 사용한다. 다음은 행동의 의미 기준이며 구현 시 친숙한 한국어로 표현한다. 새 라우트·화면 추가 지시가 아니다.

| 실제 상태 | Primary | Secondary / 제한 |
| --- | --- | --- |
| 첫 진입 / 데이터 없음 | Excel 이용내역 업로드 | 비로그인은 실제 업로드 시도 시 인증 흐름으로 연결 가능. 빈 분석을 동등한 CTA로 두지 않음 |
| 업로드 저장 완료 / 분류율 0% | 소비 내역 분류 시작 | 분석을 동등한 중요도로 노출하지 않음. 자동 분류 결과가 있으면 실제 상태에 맞는 다음 행 사용 |
| 일부 분류 완료 | 남은 내역 계속 분류 | 실제 분석 진입이 가능하면 분석은 Secondary로 유지. 미분류가 있다는 이유만으로 기존 분석을 잠그지 않음 |
| 분류 완료 | 소비 분석으로 이동 | 분류 완료는 AI 분석 성공이 아님. 자동 라우트 이동 없이 사용자가 선택 |
| 분석 실행 전 / 실행 성공 후 | 소비 분석 실행 → 개선 목표 확인 | 성공 결과가 확인되기 전에 다음 단계를 완료처럼 표시하지 않음 |
| 목표 선택 / 저장 | 목표 선택 및 저장 | 선택과 저장 성공을 구분. 저장 후 저장된 목표/상태를 확인할 경로 유지 |

분석은 현재 `/insights` 안의 실제 정보 영역과 연결한다. 기능의 실행 가능 조건·데이터 출처는 각 기능 계약을 따른다. Loading/Error/미확인 상태를 분류율 0%나 Empty로 치환하지 않는다.

### Interaction Language

인상은 **차분함 / 즉각성 / 절제 / 신뢰감**이다. 입력 인지→진행→실제 변경→성공/실패가 드러나야 하며, 시선을 끄는 장식이 목적이 아니다.

| 상태 | 기준 |
| --- | --- |
| Hover | 실제 클릭 가능성만 알림. 작은 Tone 변화·제한적 Depth·짧은 Position/아이콘 반응 중 필요한 표현 선택. 정적 정보 카드에는 클릭 가능한 카드처럼 보이는 반응 없음 |
| Pressed | 입력이 인식됐음을 즉시 표현. 큰 이동·Scale·Bounce·Glow 없이 짧고 일관된 눌림 피드백 |
| Focus | 키보드 Focus는 Hover·Selection·Success와 다른 명확한 표현. 시각적 절제를 이유로 약화하거나 제거하지 않음 |
| Loading / Disabled | 실제 진행에만 Loading 표시, 중복 실행 방지, 크기/레이아웃 안정. 실행 불가 사유를 확인 가능하게 하고 진행/미확인 값을 결과로 노출하지 않음 |
| Success | 서버 응답 등 실제 근거 뒤에만 표시. 업로드 파싱/저장, AI 생성/목표 저장을 구별. 상태 레이블과 다음 행동을 제공하고 Confetti/Celebration Burst 금지 |
| Error | 입력·선택·분석 조건과 직전 맥락 보존. 해당 작업 가까이 원인/재시도 또는 복귀 경로 제공. 실패를 빈 상태나 성공으로 치환하지 않음 |

Secondary는 Primary보다 한 단계 조용하게 반응한다. 모달 종료 후 트리거로 Focus를 복귀하고 결과 알림은 필요한 `aria-live`로 전달한다. 변화 때문에 현재 작업의 Focus를 빼앗지 않는다. 필수 의미를 Hover나 모션에만 의존하지 않는다.

### Motion

- 분류율 변경·마지막 미분류 해소·분석 결과 등장·목표 선택/저장처럼 원인과 결과를 연결할 때만 선택적으로 사용한다. Opacity, 짧은 Position, Surface 변화, Crossfade를 우선한다.
- 빠른 입력 피드백과 짧은 상태 전환을 사용하되 구체적인 시간·이동값을 새 필수값으로 고정하지 않는다. 기존 화면 명세의 시간은 선택적 참고이며, 숫자 카운팅·장식 회전·카드 등장 순서를 의무화하지 않는다.
- Continuous Motion은 실제 Loading 외에는 원칙적으로 사용하지 않는다. 분석이 끝났는데 신호가 계속 회전하거나 장식 Grid가 계속 움직이는 표현은 사용하지 않는다.
- `prefers-reduced-motion`에서는 비필수 모션을 제거하고 즉시 최종 상태를 표시한다. 중요한 CTA·결과·조작 가능 여부는 Animation 종료를 기다리지 않는다. 스크린리더에는 허위 중간 수치를 읽지 않고 실제 변경 결과를 알린다.

## 4. 사용자 언어

| 내부/기존 표현 | 제안 |
| --- | --- |
| 세척된 카드 이용 내역 | 정리한 이용내역 |
| 인사이트 생성 | 내 소비 분석하기 |
| 미분류 데이터 잔여 | 분류가 필요한 내역이 있어요 |
| 프롬프트 보기/전송 프롬프트 | 분석에 사용되는 정보 |
| 이번 달 AI 추천 목표 | 이용내역에서 고를 수 있는 목표 |
| 누적 절감액 | 검증된 근거가 없으면 표시하지 않음 |
| 절감·자산 추이 | 기준 금액과 목표 금액 / 목표 진행 상태 |

분석은 발견의 가능성을 말하고 사용자를 평가하지 않는다. “중독”, “낭비”, “충동” 같은 판단 표현은 피한다. 금액에는 **기준**, **목표**, **계획상 차이**, **확인된 실적**처럼 종류를 직접 붙인다.

## 5. Design Integrity · 디자인 확정 후 분류

### Shared

**Essential**

1. B · Signal Mint, Pretendard, Light Only, 공식 브랜드 에셋을 유지한다.
2. 상태가 정보 위계와 주 행동을 실제로 바꾼다. Empty와 Error, Loading을 같은 일반 안내로 합치지 않는다.
3. 실제 API/계산으로 근거가 없는 숫자·AI 결과·실적을 제품 화면에 표시하지 않는다. 디자인 샘플은 계속 명시한다.
4. 기존 인증·내비게이션·`/insights` 경로 및 MVP-363의 완료된 UI를 보존한다.
5. 읽기→목표 선택 사이의 CTA와 문장이 사용자의 맥락을 이어준다.

**Enhancement**

- 신호 고리는 정적 표현을 기본으로 하며, 실제 Loading에서만 제한적 모션을 허용한다. Hover Depth는 클릭 가능한 카드에만 적용하고 단색/즉시 전환으로 경량화할 수 있다.
- 영문 eyebrow와 장식적 상태 마커는 의미 위계가 유지되면 생략할 수 있다.
- 동일한 숫자 비교를 보존하면 기준/목표 막대의 시각 처리 방식은 조정할 수 있다.

MVP별 Essential/Enhancement는 각 명세 하단에 따로 기재한다.
