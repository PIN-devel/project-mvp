# MVP-364 · 소비 분석 / Discovery & Understanding

## 대표 시안

[통합 프로토타입](../prototype.html)에서 `MVP-364 · 소비 분석 → 분석 결과`를 선택한다. `분석 실행 전`, `분석 중`, `미분류 내역 있음`, `분석할 내역 없음`, `실패 및 재시도`도 각각 확인한다. 성공 장면의 24건, 요약과 카드 3개는 **Design Sample**이다. 운영 AI 성공의 증거가 아니다.

핵심 인상은 **내 기록에서 한 문장의 의미가 떠오르는 순간**이다. 페이지 제목 뒤 Navy 해석 면에는 `summary`의 핵심 문장을 크게 읽히게 하고, 오른쪽에는 분석 범위를 같은 높이로 배치한다. 세부 카드는 아래에서 따라온다. 카드 3개를 주 장면과 동일한 크기로 경쟁시키지 않는다.

## 실제 데이터 계약과 표현

| 요소 | 현재 근거 | 시안 표현 / 제한 |
| --- | --- | --- |
| 거래 범위 | `GET /api/transactions`, `GET /api/categories` | 기간·카테고리와 해당 거래 건수. 샘플 24건은 실사용 데이터 아님 |
| 기간 | `ALL`, `LAST_1_MONTH`, `LAST_3_MONTHS` | “전체/최근 1개월/최근 3개월”. 현재 FE의 최근 기간은 **최신 거래일을 기준**으로 계산하므로 오늘 기준이라고 쓰지 않음 |
| 카테고리 | `categoryId` 또는 `null` | 전체 또는 선택한 카테고리. 미분류 거래는 전체 조건에서만 포함될 수 있음 |
| 분석 요청 | `POST /api/insights` | `period`, `categoryId`, 최소 1건의 거래. 각 거래는 날짜·가맹점·금액·카테고리·태그·상태·분류 상태를 포함 |
| 응답 | `summary`, `cards[{title,description}]`, `generatedAt` | 큰 요약, 2–3개의 발견 카드, 생성 시각. 고정된 AI 카드 종류나 수치 필드는 없음 |
| 미분류 | 거래의 `isClassified` 우선, 카테고리 값 보완 | “분류가 필요한 내역” 배너. 분석 차단 조건이 아니며 카테고리 해석의 한계를 안내 |
| 결과 신선도 | 현재 FE의 `buildDataSignature` + 필터 상태 | 거래·조회 조건 변경 후 기존 결과를 새 결과처럼 두지 않음. 재분석 안내 또는 이전 조건 명시 |

현재 `generateInsightWithMonthlyGoals`는 AI 요청 성공 뒤 목표 목록을 이어서 가져온다. 목표 조회 실패가 AI 결과 표시를 막을 가능성을 Stage B에서 분리 검토한다. 목표 조회 API는 별도 존재하며 AI 응답에 목표 추천 목록이 포함되지 않는다.

## 상태 설계

| 상태 | 중심 장면 | 근거/하단 | 주 행동과 피드백 |
| --- | --- | --- | --- |
| Initial | “정리한 내역에서 나의 소비를 읽어볼까요?” | 현재 필터, 거래 건수, 분석에 전달되는 정보 | `내 소비 분석하기`. 결과·완료 성과 미표시 |
| Loading | 스켈레톤 + 읽기 중 메시지 | 요청 시점의 범위 유지. 카드도 스켈레톤 | 진행 상태만 알림. 자동으로 성공 데이터를 주입하지 않음 |
| Success | 실제 `summary` 중심의 발견 장면 | 실제 `cards` 2–3개와 `generatedAt` | `개선 목표 살펴보기`로 같은 `/insights` 내 목표 영역 연결 |
| Empty | 필터 결과 0건 | 0건을 명시, 서버 오류와 구분 | 조건 다시 보기 / 기존 이용내역으로 이동 |
| Error | “이번 분석 결과를 가져오지 못했어요” | 결과/목표 제안 숨김. 서버의 오류 원인에 맞는 안내 | 조건 보존 후 다시 분석하기. 오류는 한곳에만 노출 |
| Partial Classification | Initial/Success에 맥락 배너 | 미분류 건수와 카테고리 해석 한계 | 분석은 가능, 이용내역에서 분류하는 보조 링크 |

**데이터 부족:** 현재 서버에는 1건 이상이라는 요청 조건 외에 ‘부족’ 임계치나 독립 상태 코드가 없다. 0건은 Empty로 표현한다. 1건 이상에서 “AI가 정확히 분석하기에 부족하다” 같은 서버 정책을 만들어 말하지 않는다. 응답이 적거나 모호하면 원문 의미를 보존하고 과장된 패턴 단정을 피한다.

**초기 데이터 로딩/조회 오류:** 거래·카테고리 조회 전에는 건수와 범위를 추측하지 않는다. 조회 실패를 0건 Empty로 치환하지 않는다. 기존 앱의 Suspense와 ErrorBoundary를 사용하되 분석 요청 실패의 로컬 재시도 UX와 구분한다.

## 컴포넌트와 시선 흐름

1. 페이지 메시지: 발견 단계의 역할을 설명한다.
2. Navy 해석 면: 상태마다 제목, 설명, CTA가 바뀐다. 성공이면 원문 `summary`가 중심이다. 장식 원은 정량 그래프가 아니며 스크린리더에서 숨긴다.
3. White 근거 면: 기간, 카테고리, 대상 건수, `generatedAt`. 실행 전에는 조건 변경 가능; 실행 이후에는 해당 결과가 어느 조건인지 분명히 표시한다.
4. 발견 카드: `title/description`을 그대로 대응시키되 제목 길이와 문장 길이를 탄력적으로 수용한다. 고정된 “반복/안정/목표” 분류를 요구하지 않는다.
5. 다음 행동: 성공 응답 뒤에만 목표 선택 흐름을 강조한다. 목표 제안은 별도 FE 계산이라는 출처를 다음 화면에서 다시 밝힌다.

필터 변경 시 성공 요약을 현재 범위의 결과처럼 표시하지 않는다. 분석 요청 중 이중 제출을 막고, 실패 시 선택했던 조건을 유지한다. 재시도 성공 전까지 성공 UI로 전환하지 않는다. 실패를 토스트와 본문에 중복으로 반복하지 않는다. 프로토타입의 약 1.4초 로딩은 시연용 시간으로 실제 요청 지연과 무관하다.

## UX Writing 예시

- 시작: “정리한 내역에서 나의 소비를 읽어볼까요?” / “내 소비 분석하기”
- 범위: “분석에 사용되는 정보”, “조회 조건에 맞는 카드 이용내역”
- 부분 분류: “분류가 필요한 내역이 있어요. 카테고리별 해석은 제한될 수 있어요.”
- 진행: “선택한 내역을 읽고 핵심 내용을 정리하는 중입니다.”
- 실패: “이번 분석 결과를 가져오지 못했어요. 같은 조건으로 다시 시도할 수 있어요.”
- 결과: AI 원문의 불확실성을 지킨다. 사용자 성격·습관을 단정하지 않는다.

## Stage B-1 인계

- `AiInsightsPageContent.tsx`의 필터/요청/결과 처리와 `model/core.ts`의 범위 계산을 연결하되 제품 기능은 기존 계약 안에 둔다.
- 기존 API 실패 코드 `INS001` 시간 초과, `INS002` 서비스 불가, `INS003` 유효하지 않은 AI 응답은 단일 오류 표면에 설명하고 재시도를 제공한다. 서버/네트워크 오류를 전부 조건 오류로 돌리지 않는다.
- `summary/cards/generatedAt` 외 새로운 AI 구조를 전제하지 않는다. 카드를 2개 또는 3개 모두 처리한다.
- 프롬프트 원문 대신 사용자가 알아야 할 정보의 범위와 필터를 보여준다. 개인 거래 원문/프롬프트는 이 화면의 공개 정보로 만들지 않는다.
- MVP-374 복구 후 실제 성공 렌더링, 입력 범위, 결과→목표 통합 경로를 별도 검증한다. 이 시안은 운영 PASS가 아니다.

## Design Integrity

**Essential**

1. 실행 전 분석 대상·조건·전달 정보, 실행 행동을 한눈에 이해한다.
2. 결과의 첫 초점은 실제 `summary`이고, 실제 `cards`와 생성 시각이 보조한다. 임의로 파생한 AI 수치 그래프를 결과처럼 제시하지 않는다.
3. Loading/Error/Empty/부분 분류가 서로 다른 메시지와 행동을 제공한다. 실패에서 가상 성공으로 우회하지 않는다.
4. 성공 결과에서 목표 선택으로 이어지는 링크가 맥락을 보존하며 같은 `/insights`의 실제 동작으로 연결된다.
5. 결과의 출처와 신선도를 표시하고 조회 조건 변경 뒤 오래된 요약을 새 결과로 오인시키지 않는다.

**Enhancement**

- 신호 고리와 스켈레톤 애니메이션은 정적 상태로 대체할 수 있다.
- 카드 hover 상승과 영문 신호 번호는 생략 가능하다.
- 근거 면의 상세 정보는 접어서 보여줄 수 있으나 기간·카테고리·대상 건수는 항상 보인다.
